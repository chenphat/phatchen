# Controls (ICSR) and assurance readiness

Anchors: S1.74–86 (judgements, measurement uncertainty, errors); COSO Internal Control — Integrated
Framework (2013) and COSO *Achieving Effective Internal Control over Sustainability Reporting* (2023);
IAASB ISSA 5000 (periods beginning on or after 15 December 2026); IESBA sustainability revisions and
IESSA (effective 15 December 2026); ISA 265 concepts for deficiencies.
Working papers: S1-12 (controls matrix), S1-13 (evidence index), S1-14 (review notes, scorecard).

## 1. ICSR vs ICFR
Same COSO principles; different data (activity data, estimates, value-chain data), owners (CFO and
sustainability lead jointly, named KPI owners) and assurance (ISSA 5000 limited or reasonable).

## 2. Control cycle and key controls
Capture → validate → calculate → review → approve → report and retain. A control is not a policy:
it is performed by a named person, at a set frequency, and leaves evidence.

| Control | Example procedure | Evidence | COSO component |
|---|---|---|---|
| Completeness | Reconcile sites/meters in boundary to bills received | Site list, bill register | Control activities |
| Accuracy | Agree activity data to invoices, meter photos | Bills, logs | Control activities |
| Cut-off | Map billing cycles (meter-read dates) to period; accrue last month | Cut-off schedule | Control activities |
| Authorisation | Manager signs monthly KPI pack | Signed checklist | Control activities |
| Segregation of duties | Preparer ≠ reviewer ≠ approver | RACI | Control environment |
| Change management | Lock formulas and factors; version log | Version log | Information & communication |
| Access (ITGC) | Restrict edit rights to source files/ERP fields | User-access list | Control activities |
| Estimates | Method memo when data missing; flag as estimated | Estimate memo | Risk assessment |
| Retention | Central repository, retention aligned to accounting records | Repository index | Information & communication |
| Monitoring | Internal audit tests a sample quarterly | Test results | Monitoring |

**Maker–checker–approver** for every disclosed figure: maker prepares from source and records in the
source-data register; checker recalculates, agrees to evidence, logs exceptions; approver (department
head/CFO) signs before the figure enters the disclosure.

## 3. Audit trail and reference convention
Source evidence → data register → calculation WP → reconciliation (bills, meters, GL) → review
evidence → disclosure. Reference format: `<PILLAR>-<TOPIC>-<YEAR>-<NNN>`, e.g. ENV-ELEC-2026-001
(register), -002 (calculation), -003 (reconciliation), -004 (review/approval).
Five questions per KPI: where did it come from, who prepared/reviewed it, how was it calculated,
what evidence supports it, could someone else reproduce it?

## 4. Testing and deficiency classification
Steps: inspect KPI definition → obtain population, select risk-based sample → trace forward (source
→ disclosure) and backward (disclosure → source) → recalculate → inspect review evidence → record
exceptions, impact and action.

| Error | Example | Test |
|---|---|---|
| Incomplete | One site's bills missing | Reconcile site list to boundary |
| Duplicate | Bill recorded twice | Match bill numbers/periods/amounts |
| Calculation | kWh treated as MWh; GWP applied twice | Independent recalculation |
| Unsupported assumption | Factor outdated or unsourced | Inspect source, year, approval |
| Cut-off | December omitted | Inspect January bills, read dates |
| Unauthorised change | Formula edited | Version log, access |
| Inconsistent method | One site measured, another estimated | Compare methods; disclose |
| Greenwashing | Rounding down, omitting a site | Agree disclosure to approved register |

Classify findings as design or operating deficiencies; judge significance (ISA 265 concepts). A
variance above the review threshold (commonly 5% of the metric) is escalated; evaluate whether the
uncorrected misstatement is material to the *metric* and to users (S1.18).

## 5. Assurance standards — read the report critically
| Standard | Levels | Note |
|---|---|---|
| ISSA 5000 (IAASB) | Limited (negative-form conclusion) or reasonable (positive opinion) | Framework-neutral; primary standard from periods beginning on/after 15 Dec 2026 |
| ISAE 3000 (Revised) + ISAE 3410 (GHG) | Limited or reasonable | Earlier engagements; GHG statements |
| AA1000AS v3 | Type 1/Type 2; moderate/high | Not equivalent to ISSA 5000 levels |
"Moderate assurance, Type 2" ≠ limited assurance under ISSA 5000 — check standard, subject matter and level.

Ethics: IESBA Code s.220 (preparation and presentation of information) and s.270 (pressure) apply to
preparers; IESSA independence applies to sustainability assurance practitioners (e.g. self-review
threat if the assurer built the data system).

## 6. ICSR maturity scorecard (S1-14)
Five dimensions × 20 points:
1. Governance and leadership (board oversight of data, named executive owner, data integrity in code).
2. Policies and procedures (KPI definitions, maker-checker-approver, approved factor policy).
3. Data collection and validation (registers, ledger reconciliation, cut-off).
4. Internal review and audit (independent recalculation, control testing, deficiency closure).
5. External assurance and disclosure (evidence index, balanced disclosure, restatement policy).
Bands: 85–100 ready for reasonable assurance; 70–84 limited assurance; 50–69 developing; <50 initial.
A score based only on public reports is an estimate; a reliable score requires control testing.

## 7. Assurance-readiness journey (five steps)
1. Scope and criteria (which disclosures, which framework, which level).
2. Data inventory and KPI cards for in-scope metrics.
3. Controls designed and operating for at least one cycle; dry-run internal review.
4. Evidence index complete (S1-13) and exceptions closed or disclosed.
5. Engagement acceptance with the assurer (ISSA 5000 preconditions: suitable criteria, management
   responsibility, access to evidence); joint timetable with the financial audit.
