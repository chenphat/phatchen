# Source review and gap-analysis checklist

Work through these questions while reading the source. Record each answer as a strength, a gap or a
policy statement.

## A. Status and governance
- Is the source mandatory (regulation or standard) or guidance? Does it say that departing from it is or is not a breach?
- Does it name an owner, an approver, a version, an effective date and a review cycle? If not, that is a gap.
- Does it say who is allowed to complete or sign key forms (e.g. only the partner signs acceptance)?

## B. Scope
- Which entities or engagements does it cover, and which does it explicitly exclude?
- Is there an escalation route for excluded cases? (In audit: groups under ISA 600 (Revised), publicly traded entities, banks, insurers, significant IT.)

## C. Coverage against the standards (audit)
Tick what the source covers in depth (D), lightly (L) or not at all (N):

| Phase | Standards |
|---|---|
| Quality and acceptance | ISQM 1, ISQM 2 (EQ review), ISA 220 (Revised), ISA 210, IESBA Code |
| Planning and risk | ISA 300, ISA 315 (Revised 2019) incl. IT environment, ISA 320, ISA 240 (Revised), ISA 250, ISA 550, ISA 510 |
| Response and evidence | ISA 330, ISA 500, ISA 501, ISA 505, ISA 520, ISA 530, ISA 540 (Revised 2019), ISA 620 |
| Documentation | ISA 230 (incl. 60-day assembly and retention) |
| Completion | ISA 450, ISA 560, ISA 570 (Revised 2024), ISA 580 |
| Reporting and communication | ISA 700 (Revised), ISA 701, ISA 705 (Revised), ISA 706 (Revised), ISA 720 (Revised), ISA 260 (Revised), ISA 265 |
| Monitoring | ISQM 1 monitoring and remediation, root-cause analysis |

Every L or N becomes a gap row unless the scope deliberately excludes it.

## D. Numbers and tables
- List every threshold, range, table and worked example. Recompute the worked examples.
- Does the source cite a table it doesn't reproduce? Record it as a gap and make it a controlled Excel input. Don't fill it from memory.

## E. Timing and effective dates
- Which new pronouncements apply, and from which periods? Give a concrete year-end example
  (e.g. periods beginning on or after 15 Dec 2026 means a 31 Dec 2027 year end, with reports signed in 2028).

## F. Usability
- Are there testable rules a reviewer can apply? Turn each into a red flag.
- Does the file reference system link every procedure to a risk? Turn it into WP refs in the procedures.

## Rating guide
- **High**: without a fix, a file could look compliant while failing an ISA requirement, or a key decision has no owner.
- **Medium**: a requirement is covered but incompletely, or relies on judgement with no documented basis.
- **Low**: presentation or efficiency improvement.
